# 子 agent 批量计算架构——最终总结（按拆解方法论组织）

2026-09-15/16 三轮实验（batch-subagent → shepherd → scale-round），20 假设 18 confirmed，
5 种中断零损失恢复，70 sbatch 实际 ≈2.7 核时。证据链：`docs/evidence/` 三轮目录。

---

## 一、如何拆解需要被 sub agent 接管的任务

### 1.1 拆解判据（三个问题，按序问）

1. **"这个中间产物我愿意直接贴进主会话吗？"**——不愿意（日志、sacct 表、post 输出、
   长诊断），就该有子 agent 在中间消化。这是上下文经济学的硬判据。
2. **"这段工作里有'读非结构化文本 + 判断'吗？"**——没有（轮询、解析、传输、算术），
   它是代码工作，LLM 化只有损失（不确定、花钱、不可回放）。有，才是 agent 工作。
3. **"这段工作要跨越等待吗？"**（作业生命周期、多波推进）——要，考虑 continuable
   牧羊人；不要，一次性工人即可。

### 1.2 四类接管形态（全部实测）

| 形态 | 适用于 | 拆法 | 实测 |
|---|---|---|---|
| **一次性工人 fan-out**（prep/triage/analyst） | 无状态转换：输入明确→判断→结构化结论 | 按任务分片（每工人 2–5 体系），map-reduce 的 map；瘦委托（prompt 只给指针：清单/文件路径+taskId+变换规则）；契约 JSON 回传、拒收重试一次 | 11 任务制备 5 工人；2 失败分诊 2 工人；9 结果解读 2 工人——20 裁决零编造零拒收 |
| **continuable 牧羊人** | 有生命周期的链：提交→等待→门检→条件推进 | 按"链"分片，一链一牧羊人；**波内不结束回合**（S7 机理约束）；波间可被 send_message 注入、可 report 中途汇报 | 2 链真委托（1 链成 40.1k 有界 / 1 链被预算闸正当拦停）；冷恢复续链 |
| **确定性代码（不接管）** | 轮询/解析/传输/预算算术/sacct 对账 | 留在 mat-core，契约回放测试覆盖；服务端跑（watch-loop 零模型请求） | watch-loop/gaussian producer/efile 全程未动，474→489 测试绿 |
| **组合经理（不外委）** | manifest 操作、fan-in 汇总、预算声明、失败处置决策 | 无状态：每相位/接任全新会话+manifest 恢复；fan-in 汇总必须亲自写 | 三轮五种中断全部由"新会话+清单"接住 |

### 1.3 拆解红线（实测产生，违者即翻车）

- **瘦委托**：自含 prompt 不随规模扩展（50 任务时第 10 份 prompt 就 max-tokens 截断）。
  数据在清单/文件，prompt 只给指针，每回复 ≤3 工人。
- **深度锁 1**：工人/牧羊人不得再生子（toolFilter 挡 affordance + maxDepth 运行时硬顶）。
- **提交权可下放但必须过闸**：牧羊人带 task_ref 提交实测有效且被拦得住（SH3）。
- **规格钉死**：task 类型/方法/资源档随任务进 manifest spec，禁现场发挥（V1–V8 跑成
  opt-only 的教训）。

## 二、如何拆解工程化能力

九个工程件按职责分六层，**每层对应一次实测事故**（没有事故就没有这一层）：

| 层 | 工程件 | 职责 | 诞生的实测事故（若没有会怎样） |
|---|---|---|---|
| **状态层** | portfolio + portfolio-cli（show/stale/update/diff） | 组合状态外置：相位只进不退、台账 append-only、增量行 | 两次重启+max-tokens 截断零损失接任——状态在会话里的批次会全灭 |
| **契约层** | contracts.ts（三裁决 schema+校验+≤10 行渲染） | 层间通信的机器可执行边界：evidence ≤5 行×200 字符、converged=false 而可用须 concerns | 防日志倒灌与编造；F2 贴边收敛的细粒度判定有校验面兜住 |
| **治理层** | budget.ts + budget-hook（task_ref）+ reconcile-ledger | 预算闸（sbatch/重试/核时）在工具层拦截；估算计费 vs sacct 实际两本账 | SH3 牧羊人自治提交被当场拒绝且服从——无闸的无人值守=失控账单；两本账比值 6.51% 可审计 |
| **权限层** | overlay 角色挂载（toolFilter 白名单 + maxDepth） | 权限随角色走：制备工无 exec、分诊工只读、分析师零 exec、牧羊人禁递归 | 三个 bundle 默认 disabled 坑全靠实测抓出；隔离是引擎级（工具目录里根本没有） |
| **观测层** | fold-child-usage / reconcile-ledger / probe 系列 / evidence 纪律 | per-child token 折叠、两本账对账、零 LLM 探针、证据落盘 | per-child usage 无 API 面——不补计量成本核算缺一角 |
| **协议层** | batch-orchestrator + batch-roles 两个 skill | 无状态经理 SOP、自愈扫描、瘦委托红线、波内不结束回合、四角色纪律 | 每条纪律都是一次翻车的转化；协议让正确行为可复制 |

**拆解方法论本身**：能力沿"状态→契约→治理→权限→观测→协议"六切面分解，每个切面
独立成件（mat-core 纯逻辑 TDD / mat-tools 接线 / scripts 操作面 / skills 协议），
全部树外、489 测试绿、宿主零改动——**工程件的可独立性正是它可组合性的来源**。

## 三、sub agent 架构带来的实际收益

### 3.1 量化收益

| 维度 | solo 基线 | sub agent 架构 | 倍率 |
|---|---|---|---|
| 主会话上下文（每任务） | 28–31k 全款重付 | 边际 **2–5k** | ~7× |
| 50 任务全链主会话 | ≈1.4M（或毁灭性压缩） | **105k** | ~13× |
| 等待期模型请求 | 轮询即花钱 | **0**（通知驱动，36 通知并入单回合） | ∞ |
| 失败处理的日志进主会话 | 全量倒灌 | **0 行**（20 裁决零编造） | — |
| 集群成本 | — | 70 sbatch 实际 **≈2.7 核时**（秒级作业，闸+两本账可审计） | — |

### 3.2 质性收益（demo 给不了的）

1. **韧性成为架构性质**：5 种中断（服务重启×2、max-tokens 截断、上游 400、会话死亡）
   全部无损失恢复——因为状态在清单、判断在工人、经理可替换。
2. **自治有边界**：牧羊人在真实诱惑下（链跑到一半被拒）选择 report 原文止链——
   预算闸+协议让"敢放权"成立。
3. **质量副产**：分诊工发现上游分类器 bug；50/50 converged、能量随缩放平滑递变——
   判断力下沉反而提高了质检深度。
4. **可审计**：每次提交有台账（估算+实际两本账）、每个裁决有 schema、每次事故有
   evidence——整个批次事后可完整复盘。

### 3.3 边界（收益到此为止）

集群 I/O 吞吐不因 sub agent 加速（exec-gate 串行，提交中位 46s——200+ 任务需并行
提交面/分批经理，属新设计题）；宿主三条机理缺口（jobs 不感知/per-child usage API/
outputSchema 按次传）以树外协议绕过并已列上游反馈。

---

**一句话**：拆任务的判据是"判断力+上下文体量+生命周期"，拆工程的判据是
"状态/契约/治理/权限/观测/协议六切面各对应真实事故"；收益是 7–13× 的上下文
经济性、零日志倒灌、零等待成本、以及五种中断下零损失的韧性——**这三件事互相
成就，缺任何一环都退回 demo**。
